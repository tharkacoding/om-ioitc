Explanation

First, note that if there exists a city of state BBB that lies between two cities of state AAA, then states AAA and BBB must necessarily belong to the same group. Thus, we can merge states AAA and BBB into a single state.

If we repeat this merge until we can't, we will end up with a tree in which each node represents a disjoint set of states. Therefore, we need only to solve the problem under the assumption that each state contains exactly one city.

Note that the only case in which no merges are required is when the resultant tree consists of a single node. Otherwise, we can pick any leaf of the tree and place it alone into Group X, and all other nodes into Group Y.

Now, consider a star graph with nnn leaves. What's the minimum number of merges to reduce this star to a single node? Note that in a single merge, we can delete at most two leaves by merging two leaves: therefore, the number of total merges required is ⌈n2⌉\lceil \frac{n}{2} \rceil⌈2n​⌉.

To finish, note that this formula actually generalizes: in particular, for any tree in which all cities belong to distinct states, the number of total merges required is ⌈# of leaves2⌉\lceil \frac{\text{\# of leaves}}{2} \rceil⌈2# of leaves​⌉. To show this, consider rooting the tree at the leaf centroid, such that no subtree contains strictly more than half the leaves. We claim that in each merge, we can pick two leaves that belong to different subtrees—therefore, all leaves will unite to the root.

The left diagram shows the tree correctly rooted at the leaf centroid. The right diagram shows that if we do not pair according to this centroid, all leaves may not be united after ⌈# of leaves2⌉\lceil \frac{\text{\# of leaves}}{2} \rceil⌈2# of leaves​⌉ merges.

Merging Intersecting Components

It remains to quickly perform the first steps of merging intersecting states AAA and BBB. To do this, we can define a procedure merge(tree, root) which finds all completed components that lie strictly within tree, then returns the (potentially incomplete) component attached to the root.

Note that the returned component (marked in red) is incomplete because there still exists a city in state 2 that lies outside of this tree.

Now, merge(tree, root) may be implemented recursively as follows:

Call merge(subtree, child) for each child of root and add every node in the returned component into a set CCC.

Add root into CCC, then check whether CCC forms a complete component.

If CCC is complete, return ∅\emptyset∅; otherwise, return CCC.

Here, CCC is incomplete because it contains some but not all cities in state 1.

To finish, note that "checking whether CCC forms a complete component" is easily done by XOR hashing. For more details, check my code + comments below.
